# ADR-0008: P5 Drag Protocol and Document Docking API

> English (canonical) | [简体中文](../../zh/adr/0008-p5-drag-protocol-and-document-docking-api.md)

- Status: Accepted
- Date: 2026-07-31
- Decision maker: Atlas Maintainer (authorized for P5 gate decisions)
- Related: ADR-0002, ADR-0005, ADR-0007, HLD §10.2/§10.4, DES-INT-001~006

## Context

P5 needs to map one drag terminal intent of the root controller into a Core
operation. The existing Interaction Protocol v1 only has resize and keyboard
messages, and Core only has Tool move/reorder; there is no public operation
for Editor Tab center/directional docking. The protocol and public API must
be frozen before implementation and synchronized with golden fixtures.

## Decision

### Core API

Add `DocumentDockZone`: `Center = 0`, `InlineStart = 1`, `InlineEnd = 2`,
`BlockStart = 3`, `BlockEnd = 4`.

Add immutable public operation:

```text
DockDocumentOperation(
    DockItemId itemId,
    LayoutNodeId targetGroupId,
    DocumentDockZone zone,
    LayoutNodeId? newGroupId = null,
    LayoutNodeId? newSplitId = null,
    long? baseRevision = null)
```

- Center does not accept new Node IDs and appends to the target Document
  Group; the same-source Group returns NoChange.
- The four directions must provide non-default, mutually consistent
  `newGroupId` and `newSplitId`.
- New directional Groups are Dynamic, Expanded, and the Split defaults to a
  0.5 proportional basis.
- Operation kind: Center uses `MoveItem`; directions use the existing stable
  value `SplitItem = 5`.
- Missing targets return `TARGET_NOT_FOUND`; kind/capability/ID/policy
  rejections return existing typed failures.
- Success enters normal History; Undo/Redo restore the full topology through
  reverse/forward Snapshot patches.

### Interaction Protocol v1 additive message

`protocol.ts` remains the canonical source. The v1 union adds
`DockItemCommit`:

```text
type: "dock-item"
protocolVersion: 1
sessionId, hostId, workspaceId, generation
itemId, sourceKind, baseRevision
targetKind, targetGroupId, logicalRegion?, insertionIndex?
newGroupId?, newSplitId?
```

`sourceKind`: `document-tab | panel-header | toolbar-entry`.

`targetKind`: for Documents, `document-center | document-inline-start |
document-inline-end | document-block-start | document-block-end`; for Panels,
`panel-header-insertion | panel-region-center | toolbar-insertion |
toolbar-region | drop-scaffold`.

The Host must validate ProtocolVersion, Host/Workspace, Generation, SessionId,
IDs, and required/optional field combinations before constructing the
operation. Unknown values/versions, expired sessions, or cross-Host identity
never enter Core.

### Session and generated node identity

Each controller uses a Host-scoped monotonic session counter. New Node IDs
for directional docking are generated by the controller from HostId +
SessionId and sent with the intent; Core still validates uniqueness within
the workspace. IDs do not contain titles, ContentReference, or business data.

## Alternatives

- Passing coordinates directly to .NET: violates pointermove-zero-interop and
  Core-not-reading-DOM-geometry.
- Host generating unfrozen DTOs after receiving a direction: leaves no golden
  contract between TypeScript and C#.
- Splitting Center and the four directions into multiple public operations:
  adds surface without different transaction contracts.

## Consequences

- Core and TypeScript/Blazor PublicAPI baselines, protocol fixtures, and the
  DOM manifest must update in the same slice.
- Old v1 resize/keyboard payloads stay compatible; the new discriminator is
  additive.
- P5 introduces no persistence schema, content lifetime, or security API.

## Verification

- compile-time PublicAPI contracts;
- Core center/directional/same-source/dynamic/persistent/stale/failure/Undo/
  Redo tests;
- TypeScript golden fixtures, resolver/controller terminal-path tests;
- bUnit identity/operation mapping tests;
- browser multi-Host, stale, cancel, and pointermove-zero-callback evidence.

## Supersession

None. Changing message fields, wire values, DocumentDockZone numbers, or the
operation constructor contract requires a superseding ADR.
