# ADR-0026：代码注释与 XML 文档语言政策

> [English (canonical)](../../en/adr/0026-code-comment-language-policy.md) | 简体中文

- **状态**：Accepted
- **日期**：2026-10-23
- **决策人**：Atlas 维护者（2026-10-23 批准）
- **相关**：AGENTS.md、CONTRIBUTING.md；质量发现 CORE-P2-20

## 背景

仓库文档政策以英文为权威：`docs/en/` 是规范版本，`docs/zh/` 镜像翻译。
代码注释的演进不同。提交 `6a0494c` 明确把 C# XML 文档翻译并润色为中文。
审查基线显示：

- `src/Atlas.Core` 141/141 个 C# 文件包含中文注释或 XML 文档。
- 1,102 行源码包含 CJK 字符。
- NuGet 包提供的公共 XML 文档由这些中文注释生成。
- 异常消息和部分内部注释仍是英文，形成混合语言的公共契约
  （`DockItemId.cs` 是一个例子）。

这是有意的取舍，不是意外违规。未定义的问题是“哪种语言适用于哪类产物”。
继续不定义会让公共 API 文档与英文 SRS/ADR/HLD 不一致，并提高国际贡献成本。

## 提议决策

采用**分层政策**：

1. **公共 API XML 文档**（`PublicAPI.*` 与公共成员）：使用**英文**。这些注释随
   NuGet XML 文档发布，属于消费者可见契约。
2. **公共异常消息、诊断 ID、message key 与协议字符串**：使用**英文**；稳定标识
   保持 ASCII，不做本地化。
3. **内部注释与内部 XML 文档**：优先英文；当中文能更准确表达领域理由时允许中文，
   但同一类说明不得在同一文件中混用两种语言。新内部注释应跟随文件的主语言。
4. **仓库文档**仍以英文为权威，`docs/zh/` 镜像。本 ADR 不改变 SRS/HLD/ADR 的
   文档语言政策。

迁移是增量且不改变契约的：

- 不一次性大规模翻译内部注释。
- 在下一次公开发布前，或修改公共成员时，翻译其公共 XML 文档。
- 新公共成员从一开始就提供英文 XML 文档。
- 翻译不得重命名代码标识符。

## 备选方案

### 保持中文代码注释与公共 XML 文档

保留当前写作流程与维护者阅读偏好，但 NuGet 消费者和国际贡献者会看到与英文权威
文档冲突的中文契约文档。除非项目明确把中文作为 API 文档语言，否则不采用。

### 每个公共成员提供双语 XML 文档

`<summary>` 与 `<remarks>` 重复会翻倍维护成本并让生成的 XML 噪音化。不采用；
继续使用英文权威 + `docs/zh` 镜像模式。

### 立即翻译所有内部注释

大规模、无行为变化的改动，审阅成本高且对消费者没有直接收益。不采用；增量翻译更安全。

### 用编译器/分析器强制

没有可靠的内置“注释语言”分析器；自定义分析器增加维护成本，且无法判断混合语言的
领域理由。暂不采用；使用评审与贡献指南。

## 后果

- 公共 API 文档与英文权威文档一致。
- 内部中文理由可以保留，避免不必要 churn。
- 贡献者获得明确规则，而不是从现有文件猜测。
- 公共文档面只改变语言，不改变 API 形态；无运行时或 schema 变更。
- 需要后续盘点仍为中文的公共 XML 文档。

## 验证

- `CONTRIBUTING.md` 记录分层政策。
- 改动过的公共成员 XML 文档为英文，且构建无 CS1591 警告。
- 通过抽样审计或脚本列出仍为中文的公共 XML 文档；该清单作为文档债跟踪，
  除非发布检查表另有要求，否则不作为发布阻塞项。
- 不改变代码标识符、错误码、message key 或协议字符串的语义。

## 取代关系

无。补充现有英文权威文档政策在代码注释层的规则；不取代 AGENTS.md 或
multilingual documentation plan。
