# ADR-0027：订阅者故障诊断

> 简体中文（权威） | [English mirror](../../en/adr/0027-subscriber-fault-diagnostics.md)
>
> 状态：简体中文是权威版本；英文版本是按 ADR-0035 维护的镜像。

- **状态**：Accepted
- **日期**：2026-10-23
- **决策人**：Atlas 维护者（2026-10-23 批准）
- **相关**：ADR-0002、ADR-0003；质量发现 CORE-P2-17

## 背景

`AtlasWorkspace` 会隔离 `Changed` 与强类型域事件订阅者抛出的异常，使单个消费者
不能破坏布局提交或其他订阅者。当前隔离仅通过 `Trace.TraceError` 记录异常。
使用结构化日志、遥测或测试框架的应用无法以受支持的方式观察这些被吞掉的异常。

ADR-0003 固定了事件顺序、重入与订阅者隔离规则；本 ADR 只增加可观测性，不改变
这些语义。

## 决策

为公共 `AtlasWorkspaceOptions` 增加可选的 **init-only** 属性：

```text
Action<Exception>? SubscriberFaultSink { get; init; }
```

工厂把回调传给内部 `AtlasWorkspace`，再由其传给 `Changed` 派发器与强类型域事件
派发器。

- 异常写入 `Trace` 后调用回调。
- 回调自身异常被捕获并忽略，不得影响派发、顺序、重入或已提交操作结果。
- 未配置回调时行为不变。
- 保留原 `AtlasWorkspaceOptions` 构造函数签名；通过对象初始化器设置属性，避免
  构造签名二进制破坏与 `RS0027` 可选参数重载问题。

## 备选方案

### 增加第四个可选构造参数

源码兼容但改变构造签名（二进制兼容风险），并触发可选参数重载分析器
（`RS0027`）。不采用。

### Core 依赖 `ILogger`

会给领域层增加日志依赖，并把宿主日志抽象强加给每个消费者。Core 当前没有日志
依赖，应保持。回调允许宿主桥接到任意日志系统。

### 暴露公共订阅者故障事件

会在 workspace/域事件枢纽上增加事件，并引入相对正常事件的顺序问题。单一回调更
简单，也不会与已提交状态事件流混淆。

### 仅保留 `Trace`

现状，无结构化可观测性。作为剩余诊断缺口不采用。

## 后果

- 消费者可把订阅者故障路由到日志/遥测，或在测试中断言。
- 公共 API 增加一个 init-only 属性；构造基线不变。
- 事件隔离与顺序语义不变。
- 回调在派发线程执行；长耗时回调节流后续通知，消费者应保持轻量。

## 验证

- 订阅者故障测试：抛异常的 `Changed` 订阅者与强类型事件订阅者都能到达 sink，
  同时提交成功。
- sink 自身异常测试：抛异常的回调被隔离，两个订阅者仍会执行且提交成功。
- 现有事件顺序、重入、Dispose、stale 操作测试保持通过。
- PublicAPI 分析器记录新 init 属性。

## 取代关系

无。补充 ADR-0003 的隔离规则，增加可观测性钩子。
